## Is the reported trajectory real, and are the comparisons controlled?

### Takeaway
The improvement is real on the logged fixed FineWeb guard subset: one historical DG run improves by 0.058 BPB over roughly 2,400 updates while a same-base PG run worsens. Historical comparisons are not clean objective ablations; the current memory comparison has unusually strong first-update matching, but has only 40 logged updates and remains reward/RNG-confounded.

### Inferences
- The recurring DG improvement across source-gate choices supports a broad algorithm/optimization effect rather than that gate alone. It does not isolate DG from fresh-batch topology.
- Current identical first pool rules out initial sample differences as explanation of the first actor-gradient difference. It does not guarantee later pools/RNG alignment or reward equivalence.
- Stronger historical FineWeb BPB occurs in a run with very weak critic EV, so a learned high-quality critic is not necessary for this particular phenomenon.

### Gaps
- No fully clean long-run objective-only DG/PG pair located. Current DG starts from PG's warmed critic without abstention, while original PG uses abstention lambda1; actor-init reseeds RNG rather than restoring it. NOTES says abstention rare early, making early difference less consequential, but not zero.
- Logged guard covers only8192 fixed tokens, not full FineWeb validation. No confidence interval or independent subset evaluation was performed in this task.

## What exactly does guard/val_bpb measure?

### Takeaway
It is a fixed teacher-forced token-only LM evaluation of shared backbone and vocab renderer. It bypasses all latent injection and memory carry, so lower BPB cannot establish that the deployed reasoning policy itself has better generic language prediction.

### Cited Findings
- Trainer loads the checkpoint tokenizer's validation shard family; nano uses its configured pretraining_data_path / fineweb_val_*.bin. `bpb_val_tokens` truncates the same initial prefix to a whole number of seq_len windows. All compared manifests have bpb_val_tokens=8192. — [Validation loading](/home/marvin/Documents/repositories/parameter-golf/postraining/train_latent_vapo.py:4590), [Prefix truncation](/home/marvin/Documents/repositories/parameter-golf/postraining/train_latent_vapo.py:4602).
- The guard calls baseline.eval_val on wrapper, then logs type=bpb and TensorBoard guard/val_bpb. — [Guard call](/home/marvin/Documents/repositories/parameter-golf/postraining/train_latent_vapo.py:6052), [Logging](/home/marvin/Documents/repositories/parameter-golf/postraining/train_latent_vapo.py:7286).
- Wrapper.forward embeds observed input IDs, computes temporal_belief_from_token_latent, concatenates input embeddings with beliefs, and renders CE against next-token IDs. No carry read, memory writer, Gaussian action, or hidden injection is present. `policy_logits` explicitly documents “token-only vocab logits (no hidden injection)”. — [Renderer features and policy_logits](/home/marvin/Documents/repositories/parameter-golf/postraining/latent_thought.py:1021), [Teacher-forced forward](/home/marvin/Documents/repositories/parameter-golf/postraining/latent_thought.py:1043).
- GPT2 byte accounting uses a fixed per-token byte LUT and disables SentencePiece boundary correction. There is no changing byte denominator as policy changes. — [Byte accounting](/home/marvin/Documents/repositories/parameter-golf/postraining/train_latent_vapo.py:4561).

### Inferences
- Memory can preserve the token-only backbone indirectly by routing useful adaptation into carry modules, even though the guard never uses memory. Measuring gradient mass/parameter updates separately would distinguish this.
- The guard's improvement is a change in generic teacher-forced likelihood/calibration, not stochastic sampling temperature or top-p at evaluation; these choices affect training samples but guard CE uses untempered logits.
- Both DG and PG are RL on the model's own sampled text. “Different training data” still shares language features and vocab parameters with FineWeb; however no pretraining-loss term is present to force transfer.

### Gaps
- No token-level FineWeb losses, true-token probabilities, entropy, logit norms, domain subsets or calibration breakdown are logged. Thus semantic improvement versus logit recalibration cannot be separated from aggregate BPB.

## Which explanations fit the implementation and telemetry, and what would distinguish them?

### Takeaway
Most plausible is a combination: outcome asymmetry and noise rectification change update direction, potentially softening SFT overconfidence; fresh-batch topology also avoids PG's stale/minibatch drift. Simple “DG is a half-size gradient” is incomplete, and better FineWeb BPB may coexist with worse reasoning/filler generation.

### Cited Findings
- DG exact coefficient is A * sigmoid(A * surprisal / eta), with eta default1 and both gate/advantages detached. Positive sampled actions are reinforced, negative ones suppressed; negative-advantage suppression is attenuated most for surprising tokens. No importance ratio or PPO clipping. — [DG loss](/home/marvin/Documents/repositories/parameter-golf/postraining/core.py:1399).
- DG token objective is separate from optional Gaussian/stochastic action objective, which remains clipped VAPO. PG instead uses joint token+Gaussian score. Memory mode has no Gaussian head; thus current memory comparison isolates discrete objective more directly than latent historical runs. — [Objective routing](/home/marvin/Documents/repositories/parameter-golf/postraining/train_latent_vapo.py:3127), [Gaussian head bypass](/home/marvin/Documents/repositories/parameter-golf/postraining/latent_thought.py:990).
- Advantages are raw detached GAE, source-masked but not whitened/standardized. — [Advantage construction](/home/marvin/Documents/repositories/parameter-golf/postraining/train_latent_vapo.py:2785).
- All major compared runs use Muon trunk plus AdamW other parameters. Muon normalizes each gradient matrix before polar iteration; AdamW also adapts to gradient scale. ### Inferences
- Expansion for small |A*surprisal|: A sigmoid(A*s)=A/2 + s*A²/4 + higher terms. If conditional advantage mean is zero and second moment roughly action-independent, the second term becomes an entropy-ascent-like expected update. This is a bias from noise, not ordinary unbiased PG variance. Exact entropy ascent requires the moment independence assumption; real critic errors can be action-correlated, so do not assert it universally.
- SFT likely sharpened narrow answer/reasoning modes. A weak entropy-like or anti-forgetting push can undo excessive logit confidence and improve cross entropy on a broader held-out text distribution, even with no direct FineWeb training. That is calibration repair, not evidence that DG learned FineWeb knowledge. It is plausible rather than proven.
- Direct noise-rectification magnitude is initially small in current memory run (A std.0232, gate means near.5), but normalized optimizers may amplify small direction changes in low-rank/null gradient directions. Step1 same KL despite half trunk gradient is direct evidence against treating half coefficient as half effective update.
- As the broad DG trajectory moves below initial BPB and later climbs above it, a transient calibration/implicit regularization interpretation fits better than permanent general-language improvement. Rising entropy can briefly improve NLL from an overconfident starting point and later oversoften predictions or damage features.
- Sparse reward gradients on common/shared language features can transfer, and DG prioritizes surprising successful actions. This is a second plausible mechanism; it predicts better true-token rank/representation quality, not merely uniform temperature repair. The current logs cannot separate it from calibration.
- Historical fresh-batch DG vs multi-minibatch PG means stale importance ratios, per-pool momentum, data order, update stochasticity and clipping differ. Match fresh pool/minibatch64/64 before crediting DG alone.
- Carry may provide an adaptation reservoir: train auxiliary state rather than rewriting token-only LM. It cannot explain historical DG improvement alone, because historical comparator arms both have latent mode; nor is current memory observation sufficient to establish this reservoir theory.

### Gaps
- Diagnostic priorities (no jobs launched): (1) teacher-forced held-out NLL vs scalar logit temperature sweep, true-token rank, entropy and logit norms, across disjoint larger FineWeb subsets; (2) matched fresh-batch PG/DG, same warm critic/reward/cursor, one actor update; (3) gradient cosine and actual optimizer delta projection onto FineWeb CE gradient, split trunk/renderer/carry; (4) compare DG minus half-PG component, estimated conditional advantage second moments and teacher-forced calibration change; (5) freeze trunk/renderer vs train carry to test adaptation reservoir; (6) PG sampled surprisal telemetry is missing, so add objective-independent entropy diagnostics only if separately authorized.
- Important: do not interpret first-update equal rollout KL as equal long-run policy drift; KL is local to sampled RL contexts, while guard examines different teacher-forced contexts.
